# Accept the stable semantic identity contract

Work only from the supplied checkout and task context; external services,
current remote state, and descendant history are unavailable.

Promote the reviewed stable-identity direction into repository authority.

Define the durable contract for independently addressable mutable semantic
objects: identity is opaque and stable across rename, move, presentation,
storage-layout, and content changes; human-readable keys and labels are mutable
addresses, not identity. Typed relationships store typed stable IDs. Persist
semantic source relationships, while lookup, reverse-reference, dependency, and
cache indexes remain deterministically rebuildable runtime state.

For the current milestone, cover Document, Schema, Field definition, and Entity.
Do not add ProjectId solely because `.roproj` exists or FormulaId while a formula
is field-anchored. Keep cross-document references and collaboration machinery
deferred.

Separate invariant from mechanism: UUIDv7 may be the provisional creation
mechanism, but its timestamp and algorithm are not semantic meaning and the
generator must remain replaceable. Existing IDs must remain valid if the
generator changes.

Create the next ADR and reconcile the decisions index, canonical reconciliation
register, and any conflicting accepted authority you find in the checkout. Keep
this documentation-only; do not modify Rust code, persistence DTOs,
formula/numeric semantics, `.roproj` layout, or collaboration design.

Verify documentation consistency and report the exact commands and results.
